# 局域网匿名聊天室（lan-chat）

> 局域网内零注册、零留存的点对点匿名聊天室。**数字房间号一键连接**（推荐），或 **手动 SDP 交换**（完全离线）。消息通过 WebRTC P2P 直连，聊天内容不经过任何服务器。

## 核心卖点

- **数字房间号**：两台设备输入相同的 4 位数字即可自动连接，告别复制粘贴长 SDP
- **极致隐私**：聊天消息仅在浏览器内存中，关闭页面彻底销毁，无任何持久化存储
- **P2P 直连**：WebRTC DataChannel 点对点通信，聊天消息不经过服务器中转
- **零依赖**：Node.js 一体化服务器（静态文件 + 轻量信令），无需 npm install
- **双模式**：数字房间号模式（需本机运行 server.js）/ 手动 SDP 模式（完全离线，无服务器）

## 快速开始

### 方式一：数字房间号模式（推荐）

```bash
# 在项目根目录启动一体化服务器（默认 1808 端口，零依赖，无需 npm install）
node server.js
```

1. 设备 A、设备 B 接入**同一局域网**
2. 设备 B 浏览器访问 `http://<设备A的IP>:1808`（设备 A 本机也可直接访问 `http://localhost:1808`）
3. 两台设备在首页输入**相同的 4 位数字**（如 `8888`），点击「进入房间」
4. 连接自动建立（通常 1~3 秒），状态变为「已连接」即可聊天

> 服务器会打印本机访问地址；局域网访问地址为 `http://<本机IP>:1808`。

### 方式二：手动 SDP 模式（完全离线）

直接双击 `index.html` 或通过任意静态服务器打开，展开首页「高级：手动 SDP 连接」面板：

1. 发起方点击「创建连接」，等待 SDP 生成后复制，通过微信 / QQ 等发给对方
2. 接收方点击「加入连接」，粘贴 Offer SDP，复制生成的 Answer SDP 发回
3. 发起方粘贴 Answer 并提交，连接建立

> 注意：部分浏览器（如 Chrome）在 `file://` 协议下会限制 WebRTC，建议使用 HTTP 方式打开。

### 端口信息

| 服务 | 端口 | 说明 |

## 数字房间号模式工作原理

1. 创建方输入房间号 → 调 `POST /api/room` 创建房间 → 本机生成 WebRTC Offer 上传至 `POST /api/offer`
2. 加入方输入相同房间号 → 轮询 `GET /api/offer` 拉取 Offer → 生成 Answer 上传至 `POST /api/answer`
3. 创建方轮询 `GET /api/answer` 拿到 Answer → P2P 打通
4. 连接建立后房间号立即释放，可重复使用

信令服务器只负责在建立连接阶段交换 SDP（约几 KB 的握手信息），**从不接触、不转发任何聊天消息**；聊天消息在两端之间加密直连。

## 技术说明

| 项目 | 说明 |
|------|------|
| 技术栈 | HTML5 + CSS3 + 原生 JavaScript（ES6+）+ WebRTC API + Node.js（零依赖信令） |
| 通信方式 | WebRTC DataChannel（DTLS 加密，P2P 直连） |
| 信令方式 | 数字房间号：轻量 HTTP 信令（server.js）/ 手动模式：SDP 复制粘贴（无服务器） |
| ICE 配置 | `iceServers: []`，局域网内 host candidate 直连 |
| 消息协议 | JSON 格式 `{ __type: 'text' \| 'burn' \| 'file-meta' \| 'file-chunk' \| 'file-end', ... }` |
| 数据存储 | 无。所有数据仅存内存，不使用 localStorage / IndexedDB |
| 房间生命周期 | 10 分钟 TTL 滚动续期；连接建立后立即释放；服务端每 30 秒清理过期房间 |

### 信令 API 一览

| 方法 | 路径 | 说明 |
|------|------|------|
| GET  | `/api/ping` | 服务可用性探测 |
| GET  | `/api/ip` | 客户端 IP 反射（用于 mDNS 候选修复） |
| POST | `/api/room` | 创建房间（4 位数字，冲突返回 409） |
| GET  | `/api/room?room=xxxx` | 查询房间状态 |
| POST | `/api/offer` | 上传 Offer |
| GET  | `/api/offer?room=xxxx` | 拉取 Offer（拉取后标记对方已加入） |
| POST | `/api/answer` | 上传 Answer |
| GET  | `/api/answer?room=xxxx` | 拉取 Answer（含 offerPulled 状态） |
| POST | `/api/close` | 关闭房间（创建方取消） |

### 剪贴板兼容性设计（手动模式）

复制 SDP 采用三层防护策略，确保在各种浏览器环境（含局域网 HTTP 非安全上下文）下均可使用：

1. **Clipboard API**（HTTPS / localhost 安全上下文）——带 **800ms 超时保护**，防止窗口失焦等场景下 API 挂起导致按钮点击无反应
2. **execCommand 回退**——兼容局域网 HTTP 非安全上下文及 API 挂起场景
3. **选中引导兜底**——自动选中 SDP 全文，提示用户 Ctrl+C 手动复制

## 安全与隐私说明

- 聊天消息传输由 WebRTC 的 DTLS 加密保障，且消息本身 P2P 直连、不经服务器
- 信令服务器仅交换连接握手所需的 SDP，不接触聊天内容，房间数据 10 分钟自动过期清理
- 服务端无日志落盘（仅控制台输出），无数据库，无数据留存
- 手动模式下 SDP 交换通过第三方渠道（如微信）进行，理论上存在被旁观的风险，这是去中心化方案的已知限制

## 已知限制

- 数字房间号模式需要局域网内有一台设备运行 `node server.js` 并有 Node.js 环境
- 大文件（100MB+）传输受浏览器内存限制，建议传输中小文件
- 无自动重连机制，断线后需重新走一遍连接流程
